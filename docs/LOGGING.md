# Running Tools 使用日志设计规范

本文档规定 Running Tools 各业务模块的使用日志边界、字段、存储、查询和界面要求。日志用于
追踪用户操作和后台任务结果，不代替服务控制台诊断日志，也不得成为业务数据副本。

## 1. 模块隔离

- 每个一级主菜单拥有独立的日志入口和日志列表，例如邮件系统使用 `module=mail`。
- 前端不允许传入或切换 `module`；模块后端必须在服务端固定模块标识，防止跨模块读取。
- 平台可以复用统一的日志表、仓库和页面组件，但查询、统计、清理和导出必须按模块隔离。
- 新增一级模块时，应同时决定该模块是否需要日志入口；需要时必须使用自己的模块标识、事件分类
  和 API 路径，不能把记录写进邮件系统日志。

## 2. 记录范围

应记录：

- 会改变业务状态的用户操作及其真实结果；
- 重要的手动查询、导出和连接测试；
- 自动创建、Session 保活、IMAP 同步等后台任务的开始、成功、警告和失败结果；
- 能帮助定位一次操作的请求 ID、耗时、HTTP 状态和有限的非敏感元数据。

不记录：

- 日志列表查询本身，避免递归产生日志；
- 状态轮询、长轮询、健康检查等高频无业务变化请求；
- 前端路由切换、鼠标点击等没有服务端业务结果的行为；
- 完整请求体、完整响应体或上游原始响应。

## 3. 标准字段

所有模块日志使用同一基础结构：

| 字段 | 说明 |
| --- | --- |
| `id` | 日志唯一编号 |
| `module` | 模块标识，由服务端固定 |
| `category` | 模块内分类，例如 `alias`、`session`、`mailbox`、`automation` |
| `action` | 稳定的机器可读动作标识 |
| `level` | `info`、`warning` 或 `error` |
| `outcome` | `success` 或 `failure` |
| `summary` | 面向用户的简短结果说明 |
| `source` | `user`、`background` 或 `system` |
| `method` / `path` | 触发操作的 HTTP 方法与路由模板；后台任务可为空 |
| `httpStatus` | HTTP 状态；后台任务可为 `0` |
| `durationMs` | 操作耗时，单位毫秒 |
| `requestId` | 请求追踪 ID；后台任务可为空 |
| `detail` | 经过脱敏的补充信息，默认留空 |
| `metadata` | 少量结构化非敏感字段 |
| `createdAt` | 服务端记录时间，使用带时区时间戳 |

日志为只追加数据，不提供编辑能力。动作标识和分类一经发布应保持稳定，显示名称可以在前端本地化。

## 4. 安全与脱敏

以下内容禁止写入任何使用日志、控制台日志或接口响应：

- iCloud Cookie、Session Token、信任令牌、动态 API Key；
- Running Tools 登录密码和访问令牌、Apple ID 密码、两步验证码及 IMAP 密码；
- 邮件正文、安全 HTML、验证码内容和完整请求/响应体；
- `Authorization`、`Cookie`、`Set-Cookie` 等认证请求头。

邮箱地址、Apple ID、转发地址等个人标识默认不进入摘要或详情。确需关联目标时使用内部记录 ID、
数量或不可逆摘要。错误详情必须经过业务层脱敏和长度限制；允许保存定位失败所需的 HTTP 状态、
Apple 错误码和安全错误文案，不得保存认证头、令牌或完整业务响应体。

## 5. 存储和保留

- PostgreSQL 模式使用统一追加表，并以 `(module, created_at)` 建立查询索引。
- PostgreSQL 是生产唯一数据源；日志不得依赖会无限增长的 JSON 文件。
- JSON 仅允许测试和一次性迁移旧数据使用，不能作为生产主读或主写来源。
- 默认保留最近 30 天、每个模块最多 10,000 条；超期和超量记录由写入时的节流清理完成。
- 日志写入失败不得改变原业务请求的成功或失败结果，但应输出不含敏感信息的诊断日志。

## 6. 查询与界面

日志接口必须服务端分页并按时间倒序，支持以下筛选：

- 关键词：摘要、动作标识、请求 ID；
- 级别、分类、来源；
- 开始和结束时间；
- 每页条数 `10 / 20 / 50 / 100`，默认固定为 `10`。
- 提供模块级清理操作；清理必须由服务端执行数据库 `DELETE`，并在确认后刷新统计和分页。

日志页面使用紧凑工具栏、表格、明确的记录范围和分页。列表展示时间、分类/动作、结果、来源、
耗时和请求 ID；较长详情在宽弹窗中查看。加载、空数据、错误、长文本和移动端布局遵循
[`UI_GUIDELINES.md`](UI_GUIDELINES.md)。

## 7. 邮件系统事件分类

邮件系统使用以下分类：

| 分类 | 事件示例 |
| --- | --- |
| `account` | 添加母号、测试代理、保存代理、删除母号 |
| `alias` | 获取/导出列表、编辑、启用、停用、删除、分享链接 |
| `session` | 导入 Session、Apple Account 登录、手动检查、自动保活 |
| `mailbox` | IMAP 设置、连接测试、同步、隐藏本地邮件 |
| `automation` | 自动创建设置、立即执行、暂停、批次完成或失败 |

状态接口、邮箱同步等待、自动创建状态读取和日志查询不记录，避免前端轮询制造无效数据。
