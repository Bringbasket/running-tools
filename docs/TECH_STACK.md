# 技术栈规范

本文档定义 Running Tools 及其业务模块的统一技术栈。它是后续模块开发、部署和
代码评审的基准；如果当前版本尚未接入某项基础设施，应以“当前状态”列为准，
不得在文档或运行说明中误称为已经启用。

## 核心技术栈

| 层次 | 规范技术 | 当前状态 | 约束 |
| --- | --- | --- | --- |
| 后端语言 | Go 1.24+ | 已使用 | 业务模块使用 Go 编写，保持模块边界清晰 |
| Web 框架 | Gin | 规划接入 | 作为高性能 HTTP 网关，适配流式转发和大请求包；接入后统一路由、中间件和错误响应 |
| ORM | Ent | 已接入邮件缓存 | PostgreSQL 数据模型、代码生成和类型安全查询 |
| 前端框架 | Vue 3 | 已使用 | 使用组合式 API 和单文件组件 |
| 前端语言 | TypeScript | 已使用 | 页面、API 客户端和模块清单必须有明确类型 |
| 前端构建 | Vite | 已使用 | 开发代理和生产构建统一由 Vite 管理 |
| 主数据库 | PostgreSQL 15+ | 已接入第一批数据 | 当前保存邮件、隐藏记录和同步状态；后续保存分享、审计和任务历史 |
| 缓存与队列 | Redis 7+ | 已接入第一批能力 | 当前用于 IMAP 分布式锁；后续用于短期缓存、限流和任务协调，不能作为唯一持久化来源 |

## 配套 Go 技术组件

- **Gin**：高性能 HTTP 网关，统一处理路由、鉴权、中间件、流式转发和大请求包。
- **Ent**：PostgreSQL 数据模型管理工具。schema 作为模型单一事实来源，生成类型安全
  的客户端和查询代码。
- **pgx**：PostgreSQL 驱动（Ent 接入时优先使用 pgx 生态），连接池和事务边界由后端
  统一管理。
- **go-redis**：Redis 7+ 客户端。仅用于缓存、锁和短期任务状态，设置明确的过期时间。
- **log/slog**：使用 Go 标准库输出结构化日志，禁止记录 iCloud Cookie、API Key 等
  敏感值。
- **testcontainers-go**：集成测试需要真实 PostgreSQL/Redis 时使用；单元测试不得依赖
  外部服务。

以上配套组件是统一方向。引入代码依赖前，需要同步更新 `go.mod`、部署文件、环境变量
示例、测试和相关模块文档。

## 前端组件

- Vue 3 + TypeScript + Vite 为所有模块的基础组合。
- Vue Router 负责路由，Lucide Vue 负责图标；模块页面、类型、API 客户端和测试放在
  `modules/<模块>/frontend/`。
- 根 `frontend/` 只维护平台外壳、公共组件、鉴权、更新界面和模块注册，不放业务页面。

## 打包与发布

项目通过 `go:embed` 将 Vite 生成的 Vue 静态资源打包进 Go 二进制。发布构建统一使用
`embed` 构建标签：

```bash
go build -tags embed -o running-tools ./cmd/server
```

`-tags embed` 是发布构建约定；当前实现即使不传标签也会嵌入已有的
`internal/webui/dist`。开发模式仍可使用 Vite dev server，生产容器优先运行嵌入前端
的 Go 二进制，减少部署文件和运行时依赖。

## 数据与状态边界

当前版本提供 `json`、`dual`、`postgres` 三种存储模式。邮件正文、验证码索引、隐藏记录
和 IMAP 同步状态已接入 PostgreSQL；`dual` 用于迁移校验。iCloud Session、Apple 登录
状态和 IMAP 密码继续保存在 `data/` 的权限受限文件中。开发时必须遵守以下规则：

1. 模块只能写入自己的数据目录，不能修改其他模块的数据。
2. 敏感配置采用临时文件加替换写入，并设置所有者专用权限。
3. Session Cookie、API Key 和密码不得返回 API、写入日志或提交仓库。
4. PostgreSQL/Redis 接入后，文件状态仍可作为迁移期间的备份或降级来源，但不能出现
   两套互相覆盖的“主数据”。迁移方案须单独记录在 `docs/MIGRATION.md`。

## 后续接入顺序

后续启用数据库和缓存时按以下顺序推进：

1. 生产环境先使用 `dual` 校验邮件数据，再切换 `postgres`。
2. 将分享链接与分享会话迁移到 PostgreSQL，并为短期会话增加过期清理。
3. 创建任务执行历史和审计日志表，规定保留期与归档策略。
4. 为列表接口改用数据库分页查询，避免缓存上限提高后整批加载。
5. Session 秘密继续按最小暴露原则保存，不写入普通业务表和日志。
